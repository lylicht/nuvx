# Contributing

Contributions should preserve VYRAL's existing architecture and work only within the platform scope described in [ROADMAP.md](ROADMAP.md). Keep changes focused, avoid demo data and placeholder behavior, and do not add credentials or private user data.

## Before opening a change

1. Explain the behavior being changed and how it was verified.
2. Run the checks relevant to the files you touched. Common commands are in [README.md](README.md).
3. Keep generated build output, local signing files, and machine-specific configuration out of commits.
4. Preserve the copyright, license, and attribution notices for existing code and assets.

Use the formatters and test commands already configured by each component. If a platform or hardware target is unavailable, state that clearly rather than reporting it as tested.

By submitting a contribution, you agree that it will be distributed under the applicable project and component licenses, including GPL-3.0 where it applies.
